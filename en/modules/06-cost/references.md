## Not yet checked, or the repo's own inference

- The Message threads docs do not say clearly how the old part of the conversation is billed on a continue request. They only say "Threads do not change pricing or rate limits". The mock assumes the old part is still billed as input. This needs measuring on a real run.
- The mock's character-to-token ratio (1 token ≈ 4 characters) is the repo's own rule, not a number from the real tokenizer.
- Whether real batch results carry `usage.service_tier = "batch"`: not checked, so `estimate_cost_usd` takes `batch=True` instead of reading this field.
- Which SDK version has the helper `client.beta.messages.thread(...)`: not checked. The installed 1.17.0 does not have it yet.

## Estimated cost

5 scripts, 17 message calls and one batch of 4 requests to the default model with `MAX_TOKENS=1024` (01: 2, 02: 7, 03: 2, 04: a batch of 4 requests, 05: 6; the expiry simulation in 05 runs only in the mock). The `count_tokens` calls are free. Worst case with Haiku 5.5:

- Output: 17 × 1,024 × $0.50/MTok + 4 × 1,024 × $0.25/MTok (batch) ≈ $0.010.
- Input: the handbook is about 1,000–2,000 tokens per call, mostly billed at the cache write price of $0.125/MTok or the cache read price of $0.01/MTok; under $0.005.

The whole module costs under $0.02. Script 04 waits for the batch for at most 10 minutes; if it is not done, it prints the id so you can get the results later. This is an estimate, not yet measured with the real API.
